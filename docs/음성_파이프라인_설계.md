# 음성 파이프라인 설계 (Phase 8 선행 — 스켈레톤 단계)

목표: 실기의 내장 인터랙션(LinkSoul)을 비활성화(문서 8장 Temporary
Solutions)하고, 채팅과 같은 두뇌를 쓰는 자체 음성 루프로 대체.

## 파이프라인

```
마이크 → /aima/hal/audio/capture → VAD → STT → /agent/user_msg
                                   (기존 채팅 파이프와 여기서 합류)
/agent/reply → TTS → 스피커(PlayAudioFile / 시뮬에선 Mac 스피커)
```

- 합류 지점이 /agent/user_msg 이므로 **에이전트 코드는 무수정** —
  음성은 또 하나의 입력 채널일 뿐.
- 시뮬 검증용 목: Mac 마이크 → sounddevice로 캡처 →
  /aima/hal/audio/capture 형식으로 퍼블리시하는 브릿지 노드
  (컨테이너에 오디오 장치 패스스루가 어려우므로 호스트 측 퍼블리셔
  + DDS 브릿지 or 네트워크 스트림 필요 — 구현 시 결정)

## STT/TTS 엔진 후보 (구현 시 선택)

| 단계 | 후보 | 비고 |
|---|---|---|
| STT | faster-whisper(small, 로컬) | 무료, arm64 OK, 지연 ~1s |
|     | OpenAI/클라우드 STT API | 유료 — 비용 원칙상 후순위 |
| VAD | silero-vad (로컬) | 무료, 가벼움 |
| TTS | 실기: PlayTts 서비스 (내장 보이스) | 코드 이미 작성됨 (tools.py real 분기) |
|     | 시뮬: macOS `say` 또는 edge-tts | 무료 |
