  - SDK 2차 개발은 X2 "Ultra" 에디션 전용. 표준 X2는 SDK 미지원(사양표 2.8).
  - 컴퓨팅: PC1=모션제어(MCCU), PC2=개발용(Jetson Orin NX 16GB, 157TOPS,

  - Ultra 센서: LiDAR, RGB-D(전면), 스테레오 RGB(전면 L/R), 후면 RGB,

  - 비상정지 = zero-torque = 로봇이 그 자리에서 무너짐. 보호 프레임 권장.
  - OTA 업그레이드 조건: 배터리 >50%, zero-torque 상태, 업그레이드 중
    모션 명령 금지.
  - 내장 인터랙션: 웨이크워드 "Lingxi Lingxi"(中) / "hello lumi"(英),

4. Phase 1 — 시뮬 구동 (완료, 단 공식 시뮬 → 자체 시뮬로 대체)
--------------------------------------------------------------------------------

4-1. 공식 시뮬(aima-sim-app) 실행 시도 전 과정 (시행착오 기록)
  시도 환경: amd64 컨테이너 + Rosetta (colima vz-rosetta)
  ① Rosetta 자체는 정상 (alpine amd64에서 uname=x86_64 확인)
  ② x2_rl_deploy colcon 빌드 성공 (aimdk_msgs + controller, 1분41초)
  ③ 실행 시도 → libgflags.so.2.2 없음 → libgflags2.2/libyaml-cpp0.7 설치
  ④ → librmw_implementation.so 없음 → ROS 환경 소싱으로 해결
  ⑤ → libaimdk_msgs__*.so 없음 → 빌드 산출물 소싱으로 해결
  ⑥ → start_sim.sh가 "이미 실행 중" 오탐 종료: 스크립트의 pgrep -f가
     우리 bash -c 래퍼 명령줄의 'start_sim.sh' 문자열에 걸림.
     → 스크립트 우회, 환경변수 직접 세팅해 바이너리 직접 실행으로 전환
     (EM_APP_NAME=sim, AGIBOT_ENABLE_* 플래그, SIM_ROBOT_PATH 등)
  ⑦ → /sdk(virtiofs 마운트)에 default.yaml.dump 쓰기 실패(Permission
     denied) → 트리 전체를 컨테이너 내부 /opt/x2로 복사해 해결
  ⑧ → ★Illegal instruction in libmujoco.so.3.3.7 (mjp_pluginCount):
     MuJoCo x86 빌드는 AVX 필수인데 Rosetta는 AVX 미지원.
     → 대응: MuJoCo 3.3.7을 소스에서 -DMUJOCO_ENABLE_AVX=OFF로 재빌드
     (github.com/google-deepmind/mujoco, 컨테이너 내 빌드 성공)하여
     번들 라이브러리 교체 → 이 지점은 통과됨
  ⑨ → Illegal instruction in mujoco_plugin/libsensor_ray.so (클로즈드
     소스 LiDAR 플러그인, AVX 포함) → 모델 XML이 플러그인을 참조하지
     않음을 확인하고 플러그인 디렉토리 제거로 우회
  ⑩ → ★Illegal instruction in libaima-sim-module-mujoco.so (벤더
     클로즈드소스 시뮬 모듈 자체에 AVX) → 재빌드 불가. 최종 결론:
     "공식 시뮬은 Apple Silicon에서 실행 불가."
  잔여물: /opt/x2(컨테이너 내 복사본, AVX-free libmujoco 교체+플러그인
  비활성 상태), /opt/mujoco-src(재빌드 소스). 현 arm64 컨테이너로
  재생성되면서 소멸 — 공식 시뮬은 추후 x86 Ubuntu PC에서 원본 그대로 사용.

        (베이스 쿼터니언, 각속도, 유한차분 가속도+중력)
  - 구독: /aima/mc/locomotion/velocity (aimdk_msgs/McLocomotionVelocity)
  - 제어 방식:
      관절 = PD 홀드(kp=120, kd=4, 초기 자세 목표, ctrlrange 클램프)
      베이스 = hold_base 모드(기본 ON): 보행 컨트롤러가 없어 물리
      균형이 불가능하므로 베이스 pose를 매 스텝 고정. 이동 명령은
      목표 (x, y, yaw)를 적분해 옮기는 키네마틱 방식. 명령 유효기간
      0.5초(갱신 없으면 정지). qvel에 명령 속도를 남겨 IMU에 반영.
  - 페이싱: 100Hz 타이머 × 10 서브스텝 = 실시간 1kHz 물리.
  - 파라미터: model_path, publish_rate, kp, kd, hold_base.
  - 디버깅 기록: ①IMU가 pitch 85°로 나옴 → 구버전 코드가 실행된
    것(빌드 미반영) + 로봇이 실제로 넘어져 있었음. ②pkill -f가 자기
    자신을 죽이는 문제(exit 143) → "[s]im_node$" 패턴으로 해결.
    클린 재빌드 후 직립(쿼터니언 identity) 확인.

  - velocity 게이트: LOCOMOTION 모드 + 등록/활성 소스가 아니면

    허용(매뉴얼: locomotion 중 상지 동작 불가). 실행 시 2.5초
    애니메이션(손 흔들기/고개 끄덕임·젓기, q_ref 오프셋 방식).

  [한계 C] 응답 지연 ~3–5초 (look 포함 턴)

      판단이 걸린 턴만 상위 모델로 라우팅하는 2단 구성 검토.
  [한계 E] 시간 맥락 시각 질문 약함

  [한계 F] 장기 기억 없음

  [한계 G] get_status 빈약
    - 배터리 없음(시뮬), 위치·이동거리 미노출. 개선: x2_sim에 PmuState

      base pose를 상태 요약에 추가.
  [한계 H] speak/show_emoji가 시뮬 전용 경로
    - 지금은 /agent/say·/agent/emoji 토픽 → CLI/웹 표시. 실기에서는

  [한계 I] 프롬프트 캐싱 실효 미검증

      (Haiku 단가가 낮아 비용 영향은 작음, Sonnet 전환 시 재점검).
  [한계 J] 제어권 상실 시나리오 미검증

  [삽질 기록] ①colcon이 신규 파일(worlds.py)을 설치본에 반영 안 해

13. 팔/손 + 앉기 + 통합 home 월드 + 보행 내비 + 라이브 영상 (2026-08-07)

  13-1. 집기/놓기 (pick_up / put_down)
  - 물체 11종을 자유 물체(freejoint, density 300)로 전환 — 밀리고
    떨어지는 진짜 물리 오브젝트. worlds.py 엔트리 6번째 요소
    {'grasp': True}로 선언 (red_box, blue_cup, yellow_ball, mug, book,
    apple, orange, banana, bottle, pan).
  - 시뮬: /x2_sim/grasp|release|grasp_result|carrying(latched)|objects
    (1Hz 위치 JSON). 잡으면 오른 손목(right_wrist_roll_link) 앞에
    키네마틱 캐리(매 스텝 손 위치로 이동) — 도달 반경 0.95m(베이스
    기준), 초과 시 fail:too_far:거리 반환으로 LLM이 접근 후 재시도.
  - 에이전트: pick_up/put_down 툴이 grasp_result를 동기 대기. 상태
    주입에 holding·nearby_objects_dist_m(가까운 순 정렬) 추가 —
    "뭐 들고 있어?"는 이미지 추측이 아니라 상태값으로 답하게 강제
    (confabulation 차단 원칙의 연장).
  - [삽질] ①집기 물체가 소품(아일랜드) 위에 '항상 접촉' 상태라 충돌
    차단이 이동을 영구 봉쇄 → 차단 판정에서 grasp 물체(grasp_bids)
    접촉은 제외. ②비동기 move(즉시 리턴)가 "접근→집기" 복합 작업을
    파괴(접근 완료 전 턴 종료) → move에 wait 옵션 추가, 동기 완료 후
    주변 물체 거리를 결과로 반환해 다음 툴 판단 근거 제공.

  13-2. 앉기/일어서기 (sit_down / stand_up)
  - 실기와 동일한 McAction 코드 사용: SIT_DOWN(2000)/STAND_UP(2005).
    MC 목 TRANSITIONS에 추가(STAND계열→SIT, SIT→STAND 자동 귀결),
    시뮬 posture 시스템: sit = 베이스 z -0.23 + 힙피치 -1.35/무릎
    1.5/발목 -0.15 오프셋을 PD 목표에 병합. 실기 전환 시 코드 무수정.

  13-3. 통합 home 월드 — "순간이동이 아니라 걸어서 이동"
  - 사용자 지적("어딜봐서 이게 소파에 사과 들고 앉은 거냐")의 근본
    원인: 월드 전환=순간이동이라 위치 초기화 + 운반물 소실 + 에이전트
    거짓말("여전히 사과 들고")까지 유발. → 거실+주방을 한 공간으로
    합친 home 월드(11.4x7.6m, 칸막이 divider 2장 + 문 폭 1.4m) 신설,
    DEFAULT_WORLD = 'home'.
  - 보행 내비 _navigate(): 웨이포인트 회전→직진 10Hz 루프, velocity
    명령만 사용(실기에서 SLAM 목적지 없이 걷는 방식과 동일 — 걷는
    과정 전체가 카메라에 보임). 5초 무진행 watchdog + stop 존중.
  - [삽질→허브 라우팅] 직선 내비가 아일랜드에 걸려 소파행 실패(7초
    스턱). 해결: 방마다 가구 없는 허브 지점(hubs) + 내 방 허브→문→
    상대 방 허브→목적지별 경유점(via)→목적지 라우팅. 목적지는
    places dict {'pos','yaw','via','dock_back'}로 구조화(소파: 등지기
    yaw=π, 티테이블 북측 차선 via). 중간 웨이포인트 통과 반경 0.5m/
    최종 0.35m, watchdog 발동 시 1.5s 후진 후 1회 재시도(언스턱).
  - 소파 도킹: 정렬 후 소파에 '닿을 때까지' 저속 후진(dock_back
    0.6m) — 충돌 차단이 자연스러운 정지 역할, 0.5초 무진행이면 밀착
    완료. 착석 위치 x=5.81(허공)→6.42(소파 앞면 밀착)로 개선.
  - E2E 검증 2회: "주방 가서 사과 집어서, 거실 소파로 가져가서
    앉아줘" → 주방 보행+픽업 → 소파까지 5.0m/33초 보행(사과 유지)
    → 등지기 → 도킹 → 착석. 최종 상태 SIT_DOWN_DEFAULT, holding:
    apple, 로봇 시야에 들고 있는 사과가 실제로 보임.
  - [삽질] pkill 패턴 "[s]im_node$"가 --ros-args 붙은 프로세스와
    미매칭 → 시뮬 3개 동시 실행 사고(정체불명 '블록 0.00m'의 원인)
    → $ 제거. 백엔드도 구프로세스 2개가 8000 포트를 잡고 있어 새
    코드가 안 뜨는 사고 — PID 확인 후 정리(패턴 킬의 한계 재확인).

  13-4. 라이브 영상 (사용자: "끊긴 화면 말고 live 영상으로")
  - 병목 규명 과정(중요): 처음 가설은 "해상도를 줄이면 빨라진다"
    → 실측 결과 640x480과 160x120이 똑같이 ~1.6-1.9s/frame으로
    해상도 무관. 고정비용 분해: ①그림자맵 4096² + MSAA 4x가 프레임당
    ~1.2s (shadowsize 256 + offsamples 0 + castshadow 해제로 제거),
    ②남은 466ms의 ~96%가 로봇 자체 비주얼 메시(geom group 1, 총
    97만 정점)의 정점 처리 — 소품 전체(group 0)는 고작 수만 정점.
    드라이버는 이미 llvmpipe(멀티스레드)라 교체 여지 없음.
  - 해법 = 이중 스트림:
    · 프리뷰: 320x240, 로봇 자신의 메시를 MjvOption geomgroup[1]=0으로
      제외(1인칭이라 자기 몸은 원래 거의 안 보임) → 18ms/frame.
      전용 스레드가 10fps로 연속 렌더 → /x2_sim/preview/compressed.
    · look()용 메인 카메라: 640x480 유지(로봇 자신 포함, VLM 화질),
      그림자 제거 덕에 2Hz 타이머를 실제로 충족(실측 1.75Hz).
  - 소비자 전환: 채팅 UI 스트림과 8080 뷰어가 프리뷰 토픽 사용.
    백엔드는 프리뷰가 안 보이면(=실기) 기존 카메라 토픽으로 자동
    폴백 — 실기 전환 시 무수정.
  - 실측: 프리뷰 9.8fps (기존 0.5~2fps). 월드 전환 반영도 프리뷰
    스레드가 0.1s 내 자동 갱신하므로 즉시 렌더 특례가 불필요해짐.

  13-5. 사용자 피드백 2건 후속 수정 (같은 날)
  [착석 화면 기울어짐] 원인: 운반 물체(사과)가 '물리 접촉을 유지한 채'
    손 위치에 키네마틱 배치되는 구조 — 앉으면 손이 무릎 근처로 내려와
    사과가 허벅지 메시와 겹치고, 그 접촉력이 유연한(kp=120) 상체
    관절을 계속 밀어 시야가 롤 방향으로 기울었음. 사과 없이 앉으면
    수평인 것으로 원인 분리 확인. 수정: 잡는 순간 물체 geom의
    contype/conaffinity=0(접촉 비활성), 놓기/리셋/월드 재구성 시 복원
    (모델이 월드 캐시에 공유되므로 _build_world에서 항상 복원).
    검증: 사과 들고 착석 → 지평선 수평.
  [스튜디오 이동 실패 오보] 증상: "스튜디오로 뛰어가" → 전환은 실제로
    됐는데 에이전트는 실패 보고. 로그 대조: 에이전트 발행(08:07:23~28)
    을 시뮬이 08:07:38~47에야 처리 — 8~16초 지연. 원인: 640x480 렌더
    (~0.5s)가 2Hz로 돌며 render_lock을 94% 점유 → 전환 콜백 굶주림.
    수정 3중: ①메인 카메라 2Hz→1Hz(점유 47%, look 신선 대기 1.5s는
    여전히 충족), ②전환 직후 즉시 렌더 특례 제거(프리뷰 스레드가
    0.1s 내 새 씬 발행하므로 불필요), ③에이전트 전환 대기 2.5s→6s
    (비캐시 월드 컴파일 ~2s 감안).
  ["다 연결하라" — 공간 연결성] 종전엔 스튜디오에서 "거실 가"라고
    하면 home으로 돌아가는 게 아니라 별도 living_room 월드로 전환되는
    구조적 모순. 수정: 집 안 장소(거실/주방/현관/소파/냉장고)는 어느
    공간에 있든 ★home 자동 복귀 후 걸어서 이동으로 통일. 별도 공간
    전환은 스튜디오/사무실만 허용(단독 거실/주방 월드는 UI 드롭다운
    전용으로 강등). 복귀 시 운반물 소실은 이벤트로 사용자에게 통지.
    검증: 스튜디오에서 "소파로 가서 앉아줘" → home 복귀 → 6.6m/29초
    보행 → 도킹 → 착석.

  13-6. 사용자 피드백 2차 ("사과가 사라지면 어떡해" + "여전히 끊겨")
  [집 증축 — 순간이동 완전 제거] 스튜디오행에서 사과가 증발한 근본
    원인은 스튜디오/사무실이 여전히 '별도 월드'(전환=순간이동+상태
    초기화)라는 것. 월드 전환에 운반물을 이식하는 땜질 대신, 집을
    서쪽으로 증축해 스튜디오(서북)/사무실(서남) 방을 물리적으로 추가
    (x -5.4~8.0, 복도 경계벽 + 문 2개 폭 1.4m). 이제 에이전트의 모든
    장소 이동이 보행이고 별도 월드 전환 경로는 UI 드롭다운 전용.
    소품: 스튜디오 테이블+red_box+blue_cup+배경판, 사무실 책상+모니터
    +의자+phone(집기 가능 13종으로 증가).
  [내비 일반화 — 방 그래프 BFS] 5개 방(living/kitchen/hall/studio/
    office) + 문 5개를 그래프로 정의하고 BFS 최단 방 경로 → 허브→문→
    허브 웨이포인트 생성. 기존 y부호 2분법(side) 라우팅 대체.
  [회전 교착 2건] 아일랜드 옆에서 사과를 집은 뒤 서쪽으로 돌아설 때
    스턱 재발. 로그 실측으로 차단 페어 특정: ①팔 스침(회전 시 팔이
    가구를 스치면 롤백이 회전을 되돌려 '옆에 서면 못 도는' 교착),
    ②발끝 스침(island↔left_ankle_roll_link). 수정: 이동 차단 판정에서
    팔 계열+발목/발 링크 접촉 제외 — 가구 '진입'은 몸통/골반/무릎
    접촉이 계속 차단하므로 안전성 유지. 검증: "주방 가서 사과 집어서
    스튜디오 테이블까지" → 주방(4.3m/17s)→픽업→스튜디오(8.3m/40s),
    사과 유지, 최종 시야에 스튜디오 테이블·소품 확인.
  [라이브 영상 잔여 끊김] 토픽은 9.8fps인데 체감이 끊긴 원인: 1Hz
    고해상(640) 렌더가 돌 때마다 ~0.5s간 llvmpipe 스레드를 독점해
    프리뷰가 매초 멈칫. 수정: 고해상 렌더를 look() 호출 시에만
    온디맨드(/x2_sim/render_hq 트리거, 평시 0.2Hz 킵얼라이브)로
    전환하고 프리뷰를 15fps로 상향. 실측: 15.0fps, 최대 프레임 간격
    109ms(기존 매초 0.5s 정지). 보행 속도도 0.25→0.3m/s(안전 상한).

  13-7. 사용자 피드백 3차 ("사과 어디갔냐" + 답변 중복 + "순간이동")
  [사과 행방 추적] objects 토픽 실좌표로 확인: 스튜디오 문 앞 바닥
    (-1.87, 1.67, z=0.05). put_down이 '그 자리 손 높이에서 낙하'인데
    LLM은 "테이블에 내려놨어"라고 추측 보고한 confabulation.
  [수정 4중 — 물건 놓기를 신뢰 가능하게]
    ① put_down이 물리 안착 1초 대기 후 실착지(높이·좌표)를 데이터로
      반환 — "높이 0.84m 표면 위" vs "바닥" 구분, 거짓 보고 차단.
    ② 스튜디오/사무실 도착 시 테이블을 마주 보고 전진 도킹
      (dock_forward — 소파 후진 도킹의 전진판). '이미 근처' 조기 반환

    티테이블)는 여유 0.12m(도킹 밀착 가능), 벽/장롱류는 0.30m.
    '관통이 늘지 않는 이동 허용' 규칙으로 탈출·경계 미끄러짐 보장.
    물리 접촉은 시각 효과(팔이 가구를 스치는 등)로만 남음.
  - 부수 수정: BFS 4방향(대각 이동이 문틀 모서리를 깎던 것),
    경로 전 셀 경유(건너뛰기 직선화 금지), 언스틱 3단(후진→좌→우).
  - 검증: "침대로 가" — 문 통과 4초 도착(이전: 3연속 스턱).
  - [삽질 기록] 검증 대기 grep이 옛 감사 로그에 매칭돼 진행 중 상태를
    완료로 오판(2회) — 타임스탬프 조건으로 교체. 에이전트 학습 지도
    메모리 캐시 때문에 파일 삭제만으론 백지화 안 됨 — 재시작 필요.

  15-4. 백지 상태 E2E (최종 검증)
